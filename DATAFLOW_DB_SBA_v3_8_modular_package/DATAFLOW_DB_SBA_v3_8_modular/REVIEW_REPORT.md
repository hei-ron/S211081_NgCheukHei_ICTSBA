# DATAFLOW DB v3.8 — 會員折扣核對及按需倒數

## 本次修改
1. 根據訂單所屬 USER 的 `member_lvl`，回溯示範訂單的每項 `sale_price`：G = 9 折、S = 9.5 折、N = 不打折。這是依照目前程式 `discountRate()` 的既有定義；若 SBA 報告對會員折扣另有規定，需以報告為準。
2. 每張 `ORDERS.total` 重新計算為其 `ORDER_PRODUCTS.sale_price × quantity` 的合計，並修正購物車、結帳顯示與新訂單建立時的四捨五入一致性。
3. 倒數不再於畫面載入時自動開始。派送員可按每件包裹的「開始倒數」後，才開始該件包裹的本地模擬計時；倒數以 `Date.now()` 計算實際經過秒數，只有在至少一件包裹開始倒數後才啟動每秒刷新；所有倒數完成或停止後會清除更新 interval。
4. 狀態變更會重置該件包裹的倒數；已簽收顯示已完成，待付款顯示等待付款且不可開始。計時只存在前端記憶體，不會跨重新載入保存，也不是後端 SLA／真實物流時間。

## 會員折扣資料原則
- `sale_price` 定義為訂單成立時的實際每件成交價（含會員折扣）。
- 目前沒有會員等級歷史表，因此回溯使用示範資料中 USER 當前 `member_lvl`；若會員等級會變動，正規化設計應在訂單成立時保存 `member_lvl_at_purchase` 或折扣率，以免未來會員升級後重算歷史訂單。
- 會員折扣以每件商品四捨五入至 2 位小數，再按數量加總；`ORDERS.total` 與明細一致。此規則亦套用於購物車與結帳顯示，避免分位差異。
